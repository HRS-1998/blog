# 迭代器模式

> 提供一种方法顺序访问一个聚合对象中的各个元素，而又不暴露该对象的内部表示。

## 解决什么问题

不同数据结构的遍历方式天差地别：数组按下标、Map 按 entries、树要递归、链表要 next 指针。如果消费方（比如一个求和函数）要支持所有结构，就得为每种结构写一套遍历分支——消费方被迫了解每种容器的内部结构，容器内部表示一旦变化，所有消费方都要跟着改。

迭代器的解法：==容器自己交出一个"迭代器"，把"怎么遍历"封装在迭代器里，消费方只认一个统一接口 `next()`，一个循环吃遍所有容器。== 这样遍历逻辑归容器管，遍历消费归调用方管，两边彻底解耦。

ES6 把这个模式做成了语言协议：`Symbol.iterator`。数组、字符串、Map、Set、NodeList 全部原生实现，`for...of`、展开运算符、解构、`Array.from` 全部基于它消费——==迭代器是 ES6 里唯一被"协议化"进语言语法的设计模式，前端面试必考其原理。==

## 结构说明

- **Iterable（可迭代对象）**：实现了 `[Symbol.iterator]()` 方法的对象，调用它返回一个迭代器。
- **Iterator（迭代器）**：实现 `next()` 方法，每次调用返回 `{ value, done }`——value 是当前元素，done 标记是否耗尽。
- **消费方**：`for...of`、扩展运算符、`Array.from` 等，只按 `next()` 协议消费，不关心容器内部。

两个概念要分清（面试高频）：

- **内部迭代器**：遍历逻辑由容器自己控制，调用方只给回调——如 `Array.prototype.forEach`。缺点：无法中断（`forEach` 里 return/ break 都停不下来）、无法做"同时取两个迭代器"这类控制。
- **外部迭代器**：调用方手握迭代器，自己决定何时 `next()`、何时停——如原生 `for...of` 的底层、Generator。控制力更强。

## 原生 JS 实现

### 1. 手写 Symbol.iterator：自定义 range 迭代器

实现一个 `[start, end]` 区间对象，能被 `for...of` 直接消费：

```js
const range = {
  from: 1,
  to: 5,
};

range[Symbol.iterator] = function () {
  let current = this.from;
  const last = this.to;
  // 返回一个迭代器：只需要一个 next 方法
  return {
    next() {
      if (current <= last) {
        return { value: current++, done: false };
      }
      return { value: undefined, done: true }; // 耗尽：done: true
    },
  };
};

// 统一消费：和遍历数组写法完全一样
for (const num of range) {
  console.log(num); // 依次输出 1 2 3 4 5
}

// for...of 的手动等价写法（看懂这个就看懂了原理）
const iterator = range[Symbol.iterator]();
console.log(iterator.next()); // { value: 1, done: false }
console.log(iterator.next()); // { value: 2, done: false }
console.log(iterator.next()); // { value: 3, done: false }
// ... 直到 { value: undefined, done: true } 停止

// 签下协议，全家桶能力全部解锁
console.log([...range]); // [1, 2, 3, 4, 5]（展开运算符）
const [first, second] = range;
console.log(first, second); // 1 2（解构赋值）
console.log(Array.from(range)); // [1, 2, 3, 4, 5]
```

### 2. 外部迭代器：手写 next/hasNext（经典 class 版）

```js
// 外部迭代器：调用方完全掌控节奏，比如并行对比两个序列
class ArrayIterator {
  constructor(list) {
    this.list = list;
    this.index = 0;
  }
  hasNext() {
    return this.index < this.list.length;
  }
  next() {
    return this.hasNext() ? this.list[this.index++] : null;
  }
}

class Container {
  constructor(list) {
    this.list = list;
  }
  getIterator() {
    return new ArrayIterator(this.list);
  }
}

// 用外部迭代器同时比较两个序列是否一致（内部迭代器做不到）
function compareIterators(it1, it2) {
  while (it1.hasNext() && it2.hasNext()) {
    if (it1.next() !== it2.next()) return false;
  }
  return !it1.hasNext() && !it2.hasNext(); // 长度也要相等
}

const itA = new Container([1, 2, 3]).getIterator();
const itB = new Container([1, 2, 3]).getIterator();
console.log(compareIterators(itA, itB)); // true
```

## 前端中的应用

### 1. for...of / 展开运算符的原理

`for...of` 的执行流程：调用对象的 `[Symbol.iterator]()` 拿迭代器 → 循环调 `next()` → `done: true` 时结束。所以：

```js
// 这三个消费语法只认 Symbol.iterator 协议：
const arr = [1, 2, 3];
console.log([...arr]); // [1, 2, 3]
console.log(new Set([1, 1, 2])); // Set {1, 2}

// 普通对象没有实现协议，所以会报错（高频面试坑）
// for (const k of { a: 1 }) {} // TypeError: 对象不可迭代
// 要遍历普通对象：借助 Object.keys/values/entries
for (const [key, value] of Object.entries({ a: 1, b: 2 })) {
  console.log(key, value); // a 1  b 2
}
```

### 2. Generator：写迭代器的语法糖

上面手写 range 的痛点很明显：状态（current）要靠闭包维护，`{ value, done }` 的返回结构啰嗦。Generator 函数是**生成迭代器的语法糖**——yield 自动产出 `{ value, done }`，几行搞定：

```js
const range2 = {
  from: 1,
  to: 5,
  // Generator 函数调用后返回的正是符合协议的迭代器
  *[Symbol.iterator]() {
    for (let cur = this.from; cur <= this.to; cur++) {
      yield cur; // yield 的值就是 next() 返回的 value
    }
  },
};

for (const num of range2) {
  console.log(num); // 1 2 3 4 5
}

// 再对比：手写版要维护闭包状态 + 手动拼 { value, done }，Generator 全自动
```

### 3. DOM NodeList / Array.from

DOM 集合是"类数组"——有下标、有 length，但没实现完整的数组方法。它们通过实现 Symbol.iterator 获得被 `for...of` 消费的能力：

```js
const divs = document.querySelectorAll('div'); // NodeList

for (const div of divs) {
  console.log(div.className); // NodeList 实现了 Symbol.iterator，可直接 for...of
}

// 但没有 .map/.filter，需要 Array.from（或展开）"借"数组能力
const classNames = Array.from(divs, (d) => d.className); // 第二参可传 mapFn，一次转换
console.log(Array.isArray([...divs])); // true —— 展开后已是真数组
```

`Array.from` 的原理：检测到对象可迭代（或有 length 的类数组），就按迭代器协议逐个取出、装进新数组——所以它能收 Generator、Set、NodeList 任何可迭代物。

## 优缺点与对比

**优点**：

- 统一遍历接口，消费方一套代码吃遍所有容器，新增容器零成本接入。
- 不暴露容器内部结构（range 可以是区间、树可以按需计算），封装性好。
- 惰性求值：元素可以边迭代边产生（无限序列、大文件流），内存友好。

**缺点**：

- 每次迭代有 `next()` 调用和对象创建开销，性能敏感的热路径上不如索引循环。
- 迭代器是一次性的，耗尽后要重新获取（`iterator.next()` 永远 done）。
- 类数组没有数组方法，多一道转换成本。

### 对比：迭代器 vs Generator vs for 循环

| 维度 | 手写迭代器 | Generator | for 索引循环 |
| --- | --- | --- | --- |
| 本质 | 实现迭代协议的普通对象 | ==生成迭代器的语法糖==（yield 自动产出 value/done） | 依赖下标随机访问 |
| 代码量 | 啰嗦（闭包维护状态） | 精简，可读性最好 | 最少，但只适用于有序索引结构 |
| 惰性/无限序列 | 支持 | 支持（天然惰性，还可 yield* 委托） | 不支持（需要终止条件） |
| 中断与恢复 | next 手动控制，可暂停恢复 | next/throw/return 精细控制 | break 只能当场中断，无法恢复 |
| 性能 | 有协议开销 | 有协议开销 + 生成器调度 | ==最快，热路径首选== |
| 典型场景 | 自定义容器接入 for...of | 异步流程控制（旧 async/await 底层）、无限序列 | 数组/字符串的简单遍历 |

一句话总结：==Generator 是迭代器的工厂，迭代器是"可统一消费"的协议，for 循环是"最快但最不通用"的遍历方式。== 通用性优先选迭代器协议，性能优先选索引循环，写起来省事选 Generator。
