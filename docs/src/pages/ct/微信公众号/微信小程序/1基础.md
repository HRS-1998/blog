
### 一：微信小程序简介与开发环境搭建

**微信小程序概述**

微信小程序是一种无需下载安装即可使用的应用，它依托于微信平台，具有轻便、开发成本相对较低、用户使用便捷等特点。应用场景十分广泛，涵盖了电商购物、生活服务、社交娱乐、办公学习等诸多领域。

| 对比维度       | 微信小程序                                                       | APP（原生应用）                                                       | 网页（H5/移动网页）                                         |
| -------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------- |
| ‌**运行环境**‌ | 依赖微信客户端运行，基于MINA框架‌                                | 需在iOS/Android系统独立安装，使用原生开发语言（Swift/Java/Kotlin等）‌ | 依赖浏览器内核运行（如Chrome/Safari），基于HTML+CSS+JS技术‌ |
| ‌**安装方式**‌ | 无需下载安装，即用即走‌                                          | 需通过应用商店下载安装包并完成安装‌                                   | 直接通过URL访问，无需安装‌                                  |
| ‌**开发成本**‌ | 开发成本较低，支持跨平台框架（如uni-app/Taro）‌                  | 需针对不同平台单独开发，成本高且周期长‌                               | 开发成本中等，需适配不同浏览器‌                             |
| ‌**功能支持**‌ | 支持微信原生API（支付/地理位置/扫码等），但无法调用设备底层功能‌ | 支持完整设备功能（如摄像头、陀螺仪等）‌                               | 功能受限于浏览器权限，无法调用系统级API‌                    |
| ‌**推广方式**‌ | 依托微信生态（搜索/扫码/分享），引流成本低‌                      | 依赖应用商店排名或广告投放，推广成本高‌                               | 依赖SEO优化或链接分享，跨平台但用户粘性低‌                  |
| ‌**更新机制**‌ | 后台自动更新，用户无感知‌                                        | 需用户手动下载更新包‌                                                 | 服务器端即时更新，用户刷新页面生效‌                         |
| ‌**用户体验**‌ | 接近原生应用的流畅度，但功能复杂度受限‌                          | 交互体验最佳，支持复杂功能和高性能需求‌                               | 加载速度受网络影响，动画效果和交互流畅度较低‌               |

### 二：小程序的基础架构与页面组成

#### 1. 小程序的架构原理

微信小程序采用了双线程的架构模式，分为视图层和逻辑层。

- **视图层**：主要由 WXML（WeiXin Markup Language）和 WXSS（WeiXin Style Sheets）构成，负责小程序页面的结构搭建和样式呈现，类似于网页开发中的 HTML 和 CSS 的作用，它直接展示给用户看到的界面效果。
- **逻辑层**：使用 JavaScript 语言编写，主要处理业务逻辑、数据处理以及与视图层的数据交互等，例如响应用户的操作行为、发起网络请求获取数据后更新视图层的显示内容等。

这两层之间通过特定的数据传输机制进行通信，当逻辑层的数据发生变化时，会通过数据绑定的方式通知视图层进行相应更新；而视图层触发的事件（如用户点击按钮等操作）也会传递到逻辑层，由逻辑层来执行相应的逻辑代码。

**这种设计可以确保在进行界面渲染和用户交互时不会阻塞逻辑处理，反之亦然，从而提高小程序的性能和用户体验‌**

| 运行环境         | 逻辑层         | 渲染层           |
| ---------------- | -------------- | ---------------- |
| iOS              | JavaScriptCore | WKWebView        |
| 安卓             | V8             | chromium定制内核 |
| 小程序开发者工具 | NWJS           | Chrome WebView   |

### 三：小程序组件的使用与自定义

#### 1\. 组件的属性与事件

1 **不同组件常见属性设置**：
以 `button` 组件为例，除了前面提到的 `type`（用于设置按钮的样式类型，如 `primary` 表示主色调样式、`default` 表示默认样式等）和 `bindtap`（绑定点击事件）属性外，还有 `size` 属性可以设置按钮的大小（如 `mini` 表示小尺寸按钮），`disabled` 属性用于控制按钮是否禁用（设置为 `true` 时按钮不可点击）等。例如：

```

    <button type="default" size="mini" disabled="true">不可点击的按钮</button>
```

- 对于 `input` 组件，除了 `type` 和 `placeholder` 属性，还有 `value` 属性用于设置输入框的初始值（也可以通过数据绑定来动态更新其值），`maxlength` 属性限制输入的最大长度等。例如：

```

    <input type="text" placeholder="请输入内容" value="初始内容" maxlength="10" />
```

2 **响应组件事件触发相应逻辑**：  
 每个组件都有对应的一系列事件，当用户与组件产生交互时，相应事件就会被触发，然后执行绑定的逻辑代码。例如 `input` 组件的 `bindinput` 事件，当用户在输入框中输入文字时，该事件会不断被触发，我们可以在绑定的函数中获取输入的内容并进行处理，如下代码所示：

```

    Page({
      data: {
        inputValue: ''
      },
      handleInput: function(e) {
        // e.detail.value 可以获取到输入框当前输入的内容
        this.setData({
          inputValue: e.detail.value
        })
        console.log('输入的内容是：', e.detail.value);
      }
    })
```

在 `WXML` 文件中对应的绑定写法为：

```

    <input type="text" bindinput="handleInput" />
```

**在微信小程序中，我们无法直接通过 bindtap="handleClick(1,2,3)" 的方式传递参数，而是需要通过自定义属性 data- 的方式进行传递，并在事件回调函数中通过 event.currentTarget.dataset 来获取这些参数。**

#### 2. 内置组件

1 **导航组件（如 `navigator` 组件）**：  
 `navigator` 组件是小程序中用于页面跳转的重要组件，它通过 `url` 属性指定要跳转的页面路径，实现页面间的导航功能。例如：

```
    <navigator url="/pages/nextPage/nextPage">跳转到下一页</navigator>
```

```
    <navigator url="/pages/tabPage/tabPage" open-type="switchTab">切换到底部 Tab 页</navigator>
```

2 **其他常用组件示例**：
`image` 组件\*\*：用于在小程序页面中展示图片，通过 `src` 属性指定图片的来源路径（可以是本地图片路径或者网络图片地址），还能设置图片的宽度、高度、显示模式（如 `aspectFit` 表示等比缩放，保证图片完整显示在容器内；`aspectFill` 表示等比缩放，填满容器，可能会裁剪图片部分内容等）等属性。例如：

```
    <image src="https://example.com/image.jpg" mode="aspectFit" width="100%" height="200rpx"></image>
```

`swiper` 组件\*\*：实现轮播图效果，内部包含多个 `<swiper-item>` 子组件来展示不同的轮播内容。可以设置自动轮播（`autoplay` 属性）、轮播间隔时间（`interval` 属性）、指示器是否显示（`indicator-dots` 属性，显示小圆点指示器来指示当前轮播位置）等。例如：

```

    <swiper autoplay interval="3000" indicator-dots="true">
      <swiper-item>
        <image src="https://example.com/slide1.jpg" mode="aspectFill" />
      </swiper-item>
      <swiper-item>
        <image src="https://example.com/slide2.jpg" mode="aspectFill" />
      </swiper-item>
    </swiper>
```

### 五：生命周期

**小程序共有以下几种运行状态：**

**冷启动**：如果用户首次打开，或小程序销毁后被用户再次打开，此时小程序需要重新加载启动，即冷启动。
**热启动**：如果用户已经打开过某小程序，然后在一定时间内再次打开该小程序，此时小程序并未被销毁，只是从后台状态进入前台状态，这个过程就是热启动。
**挂起**：小程序进行后台状态5秒后，微信停止小程序 JS 线程执行，小程序进入挂起状态。若开发者使用了后台播放音乐、地理位置等能力时，小程序会持续在后台运行，不会挂起
**销毁**：如用户很久没有使用小程序或系统资源过于紧张，小程序就会被销毁，即完全终止运行。当小程序挂起30分钟后小程序会被销毁；当小程序占用系统资源过高，可能会被系统销毁或者被微信客户端主动回收

### 六：路由

**流程**

创建页面 》 配置路由 》 跳转

**配置路由**

```
{
  "pages": ["pages/index/index", "pages/list/index"],
}
```

**跳转方法**

微信小程序一共有五个页面跳转路由：
1、wx.switchTab(Object object)----跳转到 tabBar 页面，并关闭其他所有非 tabBar 页面
2、wx.reLaunch(Object object)----关闭所有页面，打开到应用内的某个页面
3、wx.redirectTo(Object object)----关闭当前页面，跳转到应用内的某个页面。但是不允许跳转到 tabbar 页面。使用wx.redirectTo不能返回到原页面。
4、wx.navigateTo(Object object)----保留当前页面，跳转到应用内的某个页面。但是不能跳到 tabbar 页面。使用 wx.navigateBack 可以返回到原页面。小程序中页面栈最多**十层**。
5、wx.navigateBack(Object object)----关闭当前页面，返回上一页面或多级页面。可通过 getCurrentPages 获取当前的页面栈，决定需要返回几层。

### 七：状态管理

#### globalData

**使用 globalData**

在小程序的 `app.js` 文件中，你可以定义 `globalData` 对象。例如：

```
    // app.js
    App({
      globalData: {
        userInfo: null,
        theme: 'light'
      }
    });
```

**访问 globalData**

在小程序的任何页面中，你可以通过 `getApp()` 方法获取到全局的 `App` 实例，然后访问 `globalData`。例如：

```
    // pages/index/index.js
    Page({
      onLoad: function () {
        const app = getApp();
        console.log(app.globalData.theme); // 输出 'light'
      }
    });
```

**修改 globalData**

同样，你可以在任何页面中修改 `globalData` 的值：

```
    // pages/settings/settings.js
    Page({
      changeTheme: function (newTheme) {
        const app = getApp();
        app.globalData.theme = newTheme;
        console.log(app.globalData.theme); // 输出新的主题值
      }
    });
```
